ENTREGA: COMANDOS PASO A PASO (modo manual, un modulo por VM, rama deploy)
==============================================================================

0. DATOS DEL DIA (completar)
------------------------------------------------------------------------------
  IP PLANIFICADOR: ______________   IP PLACA: ______________
  IP STORAGE:      ______________   IPs de los Cores: ______________________
  (ver la IP de cada VM con:  hostname -I)

1. PREPARAR CADA VM (una sola vez)
------------------------------------------------------------------------------
  Clonar (en la contrasena de GitHub va el TOKEN):
    git clone https://github.com/sisoputnfrba/tp-2026-2c-requiemso.git ~/tp-2026-2c-requiemso
    git clone https://github.com/sisoputnfrba/entrenados-pruebas ~/entrenados-pruebas
    git config --global credential.helper 'cache --timeout=36000'

  Rama de la entrega (usar 'switch', no 'checkout'):
    cd ~/tp-2026-2c-requiemso && git switch deploy && git pull

  Si las commons no estan instaladas:
    git clone https://github.com/sisoputnfrba/so-commons-library ~/so-commons-library
    cd ~/so-commons-library && sudo make install

2. COMPILAR Y PONER LAS IPs (en cada VM; repetir si cambian las IPs o el reparto)
------------------------------------------------------------------------------
    cd ~/tp-2026-2c-requiemso && ./preparar.sh
      MODULOS : los de esa VM (ej: core  /  placa  /  planificador storage  /  todos)
      IP PLANIFICADOR / IP PLACA / IP STORAGE : las mismas en todas las VMs

    cd ~/tp-2026-2c-requiemso && ./preparar-pruebas.sh
      las mismas tres IPs (escribe las IPs en todas las configs de las pruebas)
      para volver al original:  ./preparar-pruebas.sh --restaurar

3. REGLAS PARA TODAS LAS PRUEBAS
------------------------------------------------------------------------------
  - Al EMPEZAR cada prueba, en TODAS las terminales (no en los reinicios de la 04 y la 05):
      cd ~/entrenados-pruebas/entregas_finales && rm -f *.log
  - Todo se lanza desde entregas_finales (las rutas de las configs son relativas).
  - Orden: STORAGE -> PLACA -> PLANIFICADOR -> CORES, esperando que cada uno escuche.
  - runtime/<prueba> tiene que existir en la maquina de la Placa, del Storage y del
    Planificador (los comandos de abajo ya lo crean en cada una).
  - Cada Core con un ID distinto. Para un Core extra: cualquier core-K.config con otro ID.
  - No correr dos pruebas a la vez (comparten los puertos 8080, 8081 y 8082).

4. LAS PRUEBAS
------------------------------------------------------------------------------

7. SI ALGO FALLA
------------------------------------------------------------------------------
  'No se pudo abrir el archivo de configuracion'  -> cd ~/entrenados-pruebas/entregas_finales
  La Placa no arranca / 'el Job 0 no se pudo crear' -> falta mkdir -p ./runtime/<prueba> en esa VM
  'No se pudo conectar a Placa/Storage'           -> revisar IPs (./preparar-pruebas.sh) y el orden
  'Ya hay un Core conectado con el ID N'          -> lanzarlo con otro ID
  'Address already in use'                        -> quedo un modulo viejo: pkill -x <modulo>
  "'deploy' could be both a local file..."        -> usar git switch deploy
  Se cae una VM -> Ctrl-C en todo, ./preparar.sh en otra VM con ese modulo,
                   ./preparar-pruebas.sh con las IPs nuevas en todas, y repetir la prueba.
